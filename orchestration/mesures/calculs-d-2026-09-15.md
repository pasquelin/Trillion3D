## Détail par point

### D1 — Petits triangles : produit viewProj*world et déterminant 3×3 hissés par page

Fichier : `packages/sdk-browser/gpuSmallTrianglesShader.ts`. Commit : 5f24083. Retenu : oui.

Même expression, mêmes opérandes, dans le même ordre : `uni.viewProj*page.world*v` s'associe à gauche, le produit de matrices nommé une fois vaut celui refait trois fois. La passe de tri le calcule une fois pour les 64 fils d'un groupe, qui partagent la même ligne de page ; les deux passes de raster une fois par triangle, comme avant. Campagne : 0 pixel d'écart sur les quatre vues.

### D2 — Visibilité : produit viewProj*world nommé une fois dans computeTriangle

Fichier : `packages/sdk-browser/visibilityShaderId.ts`. Commit : 0ed1502. Retenu : oui.

Le produit des deux matrices était refait pour chacun des trois sommets de la boîte écran ; nommé une fois, il donne la même matrice, donc les mêmes sommets projetés et la même décision. Le partage entre les trois invocations de sommet reste impossible à l'étage sommet : aucune mémoire de groupe n'y est disponible, et `out.position` garde son association `viewProj*(world*v)`, différente de celle de la boîte. Campagne : 0 pixel d'écart.

### D3 — Compaction indirecte : préfixe parallèle par slot au lieu d'un seul fil

Fichier : `packages/sdk-browser/gpuDrawShader.ts`. Commit : d23ebaf, annulé par 991b724. Retenu : non — reporté.

Écrit, compilé et prouvé : 120 tirages sur GPU (6 à 96 slots, plafond de 1 à 4096, compte au-dessus et au-dessous du plafond, masque de sélection actif ou non) rendent `instances`, `indirect` et `groupOffsets` octet pour octet identiques à l'ancien texte. Reporté quand même : `gpuDraw.test.ts:76` épingle `@compute @workgroup_size(1)` pour `prefixGroups`, et les attentes des tests existants ne se modifient pas dans ce lot. Le commit est conservé dans l'historique puis annulé ; ouvrir cette attente est une décision du chef.

### D4 — Tuiles de lampes : compaction par rang (countOneBits) au lieu d'une boucle mono-fil

Fichier : `packages/sdk-browser/gpuLightTilesShader.ts`. Commit : 29f5c5f. Retenu : oui.

Le rang d'une lampe retenue est le nombre de bits retenus avant elle dans le masque déjà construit : même liste, même ordre croissant, même borne `maxLightsPerTile`, même compte demandé. Vérifié par simulation des deux algorithmes sur 200 000 masques tirés au sort (aucune différence) et par compilation WGSL dans Chrome. ATTENTION : la campagne ne prouve rien ici — Emerald ne porte aucune lampe de scène (`lightsActive = 0`, étape `lightLists` non mesurée sur les quatre vues), la passe n'a donc pas tourné.

### D5 — Sélection DAG : rejet par cône calculé une fois par image et par page, relu par les autres passes

Fichier : `packages/sdk-browser/gpuDagShader.ts, gpuDagResources.ts`. Commit : 2dfbea7. Retenu : oui.

`coneRejectsBox` ne dépend que de la page, de son monde et de la caméra : son résultat est le même pour les cinq passes de l'image. `dagWanted` le calcule pour chaque page visible et le dépose derrière les drapeaux de dessin (le tampon `flags` gagne une page par page) ; `dagEscalate`, `dagCheck` et `dagMask` le relisent, et ne le lisent que pour une page visible — la seule pour laquelle il a été écrit, `visible()` étant évalué avant dans chacune d'elles. L'oracle CPU `gpuDagOracle*.ts` reste un miroir exact : il recalcule une fonction pure dont la valeur n'a pas changé, donc rien à y mettre à jour. Campagne : hash de l'ensemble sélectionné identique et 0 pixel d'écart sur les quatre vues.

### D5b — Fusion de dagCheck et dagMask

Fichier : `packages/sdk-browser/gpuDagShader.ts`. Commit : —. Retenu : non — écarté.

Impossible sans changer le résultat : `dagCheck` pose `work[worldCount+w]` pour un cluster, et `dagMask` lit ce mot pour tous les clusters du même monde. Fusionner les deux dans une passe ferait lire à un cluster une valeur que les autres clusters de son monde n'ont pas encore écrite — le drapeau de dessin dépendrait de l'ordonnancement. La barrière entre deux dispatchs est justement ce qui rend le résultat déterminé.

### D6 — Comparaison au carré pour éviter length()

Fichier : `packages/sdk-browser/gpuDagShader.ts`. Commit : —. Retenu : non — reporté.

Aucune des deux racines n'est comparée à un seuil seulement. `projected()` rend une valeur : elle est comparée dans `selects`, mais aussi rangée telle quelle par `escalate` (`atomicMax(&work[world], bitcast<u32>(parentPixels))`) — la division ne peut pas disparaître, et `error*stretch*focal > threshold*distance` n'arrondit pas comme `(error*stretch*focal)/distance > threshold`. Dans `coneRejectsBox`, `dist` et `radius` servent tous les deux juste après (`toCam/dist`, `asin(clamp(radius/dist,…))`) : remplacer `dist<=radius` par une comparaison au carré n'économise aucune racine. Condition posée par le lot non remplie, donc reporté.
