# Correction fixture — `zip` driver, container

A container must change nothing about the scene it wraps. The fixture is therefore double: the same
glTF scene **inside** its archive and **outside** it. The golden (`../../src/tests/zip_golden.rs`)
compiles both through the shared harness, compares the second against the first — cache key included,
which proves that the two compilations are one — then compares the first against
`expected.json`.

| file                    | what it pins                                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------------------------ |
| `scene.zip`             | the archive: a single root folder `scene/`, a `.gltf`, its `.bin` and a texture in a subfolder         |
| `hors-archive/`         | the contents of `scene.zip`, extracted once and for all: the same scene without a container            |
| `sortie-de-dossier.zip` | an entry `../escape.gltf`: escape from the extraction folder, refused `ARCHIVE_PATH_ESCAPE`            |
| `tronquee.zip`          | 31 of the 4,406 bytes of `scene.zip`: the central directory is missing, rejection `ARCHIVE_UNREADABLE` |
| `vide.zip`              | the 22 bytes of an archive with no entry: rejection `ARCHIVE_EMPTY`                                    |

What each choice puts under watch:

- **a single root folder**: the archive delivers `scene/`, the driver traverses it and routes its
  contents; a wrapping root must never become a scene level;
- **an external buffer** (`geometry.bin`): files neighbouring the glTF are extracted and re-read at
  the same place, otherwise the source manifest does not recompute identically;
- **a texture in a subfolder** (`textures/checker.png`): the archive's relative URIs are
  not rewritten, the container flattens nothing;
- **the three trap archives**: each is refused by its own code, and nothing is extracted.

## Provenance and licences

- `scene.zip`, `tronquee.zip` and `hors-archive/`: WebGeometry corpus
  (`test/assets/archives/gltf-nested-zip` and `test/assets/limites/truncated-zip`), **CC0-1.0**, see
  [LICENSE.txt](LICENSE.txt). `test/assets/` is not tracked by git: these bytes are copied here
  so the golden holds without it.
- `sortie-de-dossier.zip` and `vide.zip`: synthetic, written for this test, with no third-party
  content. They are regenerated by

  ```sh
  python3 -c "import zipfile; zipfile.ZipFile('vide.zip','w').close()"
  python3 -c "import zipfile; z=zipfile.ZipFile('sortie-de-dossier.zip','w'); z.writestr('../escape.gltf','{\"asset\":{\"version\":\"2.0\"}}'); z.close()"
  ```

  They are written by an external tool, and not by the crate the driver uses to read:
  a trap archive must come from somewhere other than the reader it puts on trial.

## `expected.json`

The selected driver, the `zip` → inner driver chain published in the report, the three rejection codes, and
the scene — format version, binary sidecar version, sha256 of `clusters.bin`, primitive, node
and triangle counts. The cache key does not appear in it: it holds the fingerprint of
the whole compiler implementation, so an unrelated change would move it. It serves
the equality of the two compilations, which is the real subject. `case` and `rule` are prose only, the
test strips them before comparing.
