# Golden fixture — DDS driver

The golden `src/plugins/tests/dds.rs` works on two materials.

## 1. A 4 × 4 pixel block per codec, written in the test

The tiny containers are not files: they are built byte by byte by
`src/plugins/tests/dds/bytes.rs`, `DDS_HEADER` field by `DDS_HEADER` field, and each block
carries endpoints whose reconstruction is computed by hand from the specification.

| codec | how it is named | what it puts under watch |
| --- | --- | --- |
| BC1 | `DXT1`, then `DXGI_FORMAT_BC1_UNORM` | the two 565 endpoints and the integer thirds `(2·c0 + c1)/3` |
| BC2 | `DXT3` | the explicit four-bit alpha, expanded as `v << 4 \| v` |
| BC3 | `DXT5` | the three-bit alpha ramp and its six integer sevenths |
| BC4 | `ATI1` | a single interpolated channel, rendered as red, the rest zero and alpha 255 |
| BC5 | `ATI2` | two independent ramps, in red and green |
| BC7 | `DXGI_FORMAT_BC7_UNORM` | mode 6: seven-bit endpoints, P bit, four-bit indices |
| RGBA8, BGRA8, BGRX8 | bit masks, then `dxgiFormat` | byte order, and the opacity of `BGRX8` |

The two extreme BC7 blocks are placed on indices 0 and 15, whose weights equal 0 and 64:
the reference therefore contains no interpolated value, only the endpoints themselves.

## 2. Two real files, taken from the corpus

| file | origin | what it proves |
| --- | --- | --- |
| `bc1-mips.dds` | `test/assets/textures/dds-matrix/bc1-mips.dds` | a header written by a third-party encoder is read; 256 × 256, nine levels, only level 0 comes out; the chain is counted, one byte less and the file is refused |
| `tronque.dds` | `test/assets/limites/truncated-dds/truncated.dds` | 31 bytes out of 43,832: the magic is there, the header is not, and the rejection is named |

Both are **CC0-1.0** (<https://creativecommons.org/publicdomain/zero/1.0/>), WebGeometry
corpus, generated by `test/assets/tools/texture_assets.py` on 15 September 2026, and their
levels were re-read by an independent decoder (Pillow 12.2.0) before entering the corpus. The
`test/assets/` folder is shipped off git: they are copied here so the golden does not depend on it.

The `bc3-mips.dds`, `bc5-mips.dds`, `bc7-mips.dds` and `bc1-no-mips.dds` of the same folder cover the
same matrix at large size. The driver was run over them during development: the five
files decode, at 256 × 256, with constant blocks throughout. They are not
committed — two hundred and fifty kilobytes of pixels that cannot be written in the clear do not make
a minimal fixture, and the blocks of the test above say the same thing exactly.

## Provenance of the reader

- `DDS_HEADER`, `DDS_PIXELFORMAT`, `DDS_HEADER_DXT10` headers and `DXGI_FORMAT` values: written
  from Microsoft's public “DDS — Programming Guide” documentation. No editor SDK.
- Block reconstruction: crate `texture2ddecoder` 0.1.2, MIT or Apache-2.0,
  `UniversalGameExtraction/texture2ddecoder`, pure Rust, notices kept with the dependency.
