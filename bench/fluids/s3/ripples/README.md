# S3 ripple candidate

This isolated spike implements **linearised shallow water** around a uniform mean depth, using a Rusanov flux. It is not a production ocean, bathymetry solver, shoreline model or nonlinear breaking-wave simulation. Both backends execute the same stencil on two RGBA16F textures: height perturbation, x velocity, z velocity and an unused zero channel.

For cell spacing `dx`, mean depth `H`, wave speed `c = sqrt(9.81 H)`, and fixed tick `dt`, the update is the centred shallow-water flux plus `c dt / (2 dx)` times the four-neighbour diffusion stencil. All three components then receive `exp(-damping dt)`. Out-of-grid cells are zero. Construction refuses `2 c dt / dx > 1`. The measured candidates are 256²/512² at 30 Hz, plus 15 Hz for distant-water cost; 384²/7.5 Hz are accepted experimental inputs but are not retained tiers. Defaults are extent 64 m, mean depth 0.01 m and damping 0.4/s. A candidate is not a measured recommendation.

`createWebglRipples(gl, spec)` and `await createWebgpuRipples(device, spec)` return `step(elapsed, encoder?, frame?)`, `texture()`, `bytes` and `dispose()`. WebGPU uses the supplied command encoder without submitting it. The harness must submit a frame before calling the next step: its uniforms and instance buffer are deliberately reused. The step result is also reused, so retained observations must copy its counters. `frame` contains a world-space x/z camera and up to 64 accepted `[x, z, radius, heightImpulse]` splats. Extra or wholly outside splats are counted as dropped. The fixed clock reports dropped catch-up ticks separately.

One instanced-quad draw adds the impulses directly to the current height target, including frames with no simulation tick. It never samples that target. Subsequent ticks read it and write the other target, so an impulse is not consumed twice during catch-up. Both backends use RGBA16F additive blending; WebGL admits half-float colour targets and checks framebuffer completeness. It never asks for `EXT_float_blend`, which would add 32-bit blending. Context loss or missing half-float targets is an explicit refusal.

The camera origin stays in Float64. It snaps to whole cells; a separate recenter pass copies the overlap to the other texture and fills entering cells with zero. A teleport across the domain resets it. WebGL framebuffer y grows with world z; WebGPU texture y does too, using the opposite clip-space sign in the splat vertex shader. Thus both layouts use the same row-neighbour stencil.

Two textures consume 1 MiB at 256² or 4 MiB at 512². Each backend also allocates a 1 KiB instance buffer; WebGPU adds an extent uniform and five independently aligned step-uniform slots. `bytes` includes these declared resources, not opaque driver/pipeline overhead. CPU staging and work records are fixed and reused. Four catch-up ticks are the maximum; a stalled tab cannot dispatch an unbounded burst.

Tests cover scheduling, CFL/input refusals, 64/65 splats, retained sub-tick impulses, recentring, local precision at 10 km, independent uniforms for catch-up, disposal, and WebGL sampling/attachment separation. WGSL is parsed and validated by Naga; both GLSL ES 3.00 programs are syntax/link checked with glslang. Those checks do not execute a GPU or establish cross-backend numerical agreement, visual fidelity or performance. GPU timings and retained-tier decisions remain the separate recipe run's proof.
