# Learning portal maintenance

The learning portal, https://www.trillion3d.com, is a React application with hash routes
(`#/<locale>/...`), written in TypeScript under `site/` and built into `dist/site/`, which git
ignores. This page is a map: each rule lives in the header of the file named, which is the contract.

| Folder | Role |
|---|---|
| `site/app/` | the portal: primitives `ui/`, layouts `layout/`, pages built only from both |
| `site/content/`, `site/demos/` | entries, API reference, examples list; per-entry demos |
| `site/i18n/`, `site/examples/i18n/` | the portal's and the examples' words, one file a language |
| `site/examples/` | one standalone HTML file per example, and the kit (`site/examples/kit/`) |
| `site/assets/`, `site/data/`, `site/reports/`, `site/styles/` | served as they are, or styles |

## Build and preview

1. `pnpm build:docs` (`scripts/docs/build.ts`) writes `dist/site/`; every consumer builds the same
   tree through `buildSite()` in `scripts/docs/site.ts`.
2. `pnpm docs:serve` (`scripts/docs/serve.ts`) builds, then serves `dist/site/` on
   `http://127.0.0.1:4177` (`PORT` overrides).
3. `pnpm docs:dev` (`scripts/docs/dev.ts`) serves the same tree, rebuilds what a change under
   `site/` or `packages/` reads, and reloads open pages.
4. `pnpm run compile:caches` (`scripts/site-caches.ts`) compiles the scene caches git never tracks;
   `pnpm run check:site-types` and `check:no-js` hold `site/` to strict TypeScript.

### Deploy

`.github/workflows/pages.yml` builds and publishes the site on a push to `main` (a pull request's
site is built by `validate`); its comments state each step. A manual run publishes only from `main`:
`gh workflow run pages.yml -f deploy=true --ref main`.

## Add an example

1. Write `site/examples/<id>.html`: a `<canvas id="view">`, no import map, a module script
   importing from `../runtime/engine.js` and the kit `../runtime/kit.js` (`site/examples/kit/`).
   No visible word in the page: the words go in `site/examples/i18n/<code>.json`
   (`site/examples/kit/words.ts`). Live counters describe the current browser and scene, never a
   comparison.
2. A scene around an imported model: add it to `scripts/docs/examples/models.ts`, credit it in
   `site/assets/examples/CREDITS.md`, then `pnpm build:native` and
   `node scripts/docs/examples-assets.ts <scene>`.
3. Add its entry to `site/content/gallery-roadmap.json`, in learning order within its theme; the
   entry statuses are stated in `site/app/examples/list.ts`.
4. Declare its thumbnail moment, `<meta name="thumbnail" content="3">`; the recette captures it
   (`scripts/docs/examples-thumbnails.ts`, listed by `pnpm run check:thumbnails`).

A scene too heavy to cook here lives in https://github.com/pasquelin/Trillion3D-openworld, served
under `/openworld/`.

## Add or translate documentation

1. A guide or a note: an entry with a stable id in `site/content/entries/*.ts`, its words under
   `written.<id>` in every `site/i18n/<language>.json`. Names, signatures, module paths and code
   examples are never translated.
2. An API symbol: write its TSDoc, run `pnpm run generate:api`
   (`scripts/generate-api-reference.ts`), then add its text to every
   `site/content/reference/api.<language>.json`.
3. New interface text: a key in every dictionary, read with `useWords(locale)` (`site/app/i18n.ts`).

### Languages

A language is added by its `site/i18n/<language>.json` (with its `meta`, read by
`site/content/i18n/languages.inline.ts`), its `api.<language>.json` and its
`site/examples/i18n/<code>.json`. Two gates in `validate` hold the translations:
`pnpm run check:i18n` (`scripts/check-i18n.ts`) to English's keys, and
`pnpm run check:translations` (`scripts/check-translations.ts`) to English's text, with its
`--write` and `--accept <entry>` options.

## What the tests read from the site

- `tests/integration/documentation-portal.test.ts`: every entry's symbols are exported by the file
  it names, and every demo belongs to an entry.
- `scripts/docs/i18n.test.ts` and `scripts/docs/api-reference.test.ts`: the dictionaries keep the
  technical fields; the reference covers every export with its own summary.
- `tests/fixtures/scenes/kinetic-garden/` and `mountain-terrain/`: test scenes the site never
  serves, regenerated by `pnpm docs:scene` and `pnpm docs:gallery` (`scripts/docs/scene.test.ts`);
  provenance in [ASSET_LICENSE_AUDIT.md](ASSET_LICENSE_AUDIT.md#licence-table-of-every-asset).
- The Measurements route reads `site/reports/`, written by
  [the published reports](../bench/runner/README.md#published-reports).
