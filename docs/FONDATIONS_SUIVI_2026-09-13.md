## Streaming et transformations : preuve partielle

- Les lectures de pages partagent une file priorisée et dédupliquée. La concurrence et la somme des tailles déclarées en transfert sont bornées ; une page plus grande que la limite est admise seule pour éviter une attente permanente. Une annulation retire son demandeur et interrompt le transfert uniquement s'il n'en reste aucun. Les tests couvrent la priorité et une requête partagée annulée.
- Les matrices d'instances existantes sont relues à chaque rendu dans les chemins de référence, exact, ThreeLOD et WebGPU. Une matrice modifiée invalide le résultat différé de sélection GPU ainsi que l'historique Hi-Z. Le chemin autonome accepte maintenant l'ajout, le déplacement et le retrait d'instances ; les autres chemins ne les acceptent pas encore.
- Validation de ce lot : `npm run build`, `npm test` (322/322), `npm run check:structure`, `npm run check:dts`, `npm run check:links`. Aucune campagne matérielle ni comparaison d'images n'a été exécutée pour ce lot.

## Regroupement GPU : preuve partielle

- Le regroupement stable en six catégories calcule les comptes par groupes de 64 pages, leurs préfixes, puis distribue les pages en parallèle. La petite passe de préfixes par groupes reste séquentielle ; la sélection de hiérarchie et la préparation de la table de dessin passent encore par le CPU. Le regroupement seul ne constitue donc pas une chaîne de rendu entièrement pilotée par GPU.
- Le shader réel a produit sur Chrome/WebGPU et Apple Metal (`metal-3`) les mêmes 130 identifiants ordonnés et six commandes indirectes que l'oracle CPU, y compris aux frontières des groupes. Commande : `LAB_ROOT=/Users/pasquelin/Applications/render-tech-lab node --experimental-strip-types test/webgpuDraw.browser.mjs`.

## Lot suivant : raster, textures, LOD, scène et compteurs

- Le WebGPU oriente les triangles dont la boîte projetée mesure au plus 7×7 pixels, entièrement dans le frustum, vers deux passes de calcul atomiques (profondeur puis ID). Une passe de résolution écrit dans les mêmes cibles de visibilité et de profondeur que le matériel. Le chemin matériel conserve les triangles coupés ou plus grands ; si le calcul n'est pas disponible ou dépasse le budget de cibles, il garde tous les triangles. Un essai Chrome/Apple Metal sur un triangle a lu ID `65536`, fond `0` et profondeur `0,5`, sans erreur de validation ; une scène texturée intégrée a rendu le triangle avec ce chemin actif. Il reste à comparer les pixels, profondeurs et ID sur plusieurs scènes, silhouettes, matériaux masqués et interactions Hi-Z avant de déclarer la parité générale.
- Les atlas de textures WebGPU commencent sur un repli blanc ou normal neutre. Les données source passent sur le GPU selon `maxTextureTransferBytesPerFrame` (16 Mio par défaut) ; une texture trop grande reste sur le repli et `textureSkipped` l'indique. `textureUploaded` et `texturePending` suivent la progression. Le test Chrome avec deux textures de 16 octets et un budget de 16 octets observe une texture transférée à la préparation, puis deux après un rendu. Les images glTF sont encore décodées à l'ouverture et les atlas GPU sont alloués en entier : la résidence mémoire et le chargement réseau ne sont pas encore progressifs.
- Les compilateurs JS et Rust rejettent une réduction qui changerait la frontière d'arêtes orientées et remplacent l'erreur QEM heuristique par la diagonale AABB de la région source. Cette borne vaut aussi pour la sélection GPU. Les caches précédents sont rejetés par `STALE_CACHE`. La sélection garde déjà une couverture résidente pendant les transitions ; la borne reste conservative et peut retarder fortement la simplification.
- Le Hi-Z invalide l'historique si la matrice de vue ou la projection change, y compris aux coupures de caméra. Les transformations d'objets invalident aussi l'historique. Le chemin WebGL2 autonome accepte une instance supplémentaire, son déplacement et son retrait, ainsi que le remplacement d'un matériau ou d'une page préparée. `renderViews` capture plusieurs poses successivement. Ces mutations ne sont pas encore généralisées au WebGPU.
- `totalSubmittedTriangles` explicite le total des triangles soumis avec les passages transparents ; `triangles` dans les métriques de l'explorateur utilise ce total. Les autres compteurs conservent leur sens par backend et ne constituent pas encore une instrumentation GPU physique commune.
