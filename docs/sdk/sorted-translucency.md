# Sorted translucency
`world.orderIndependentTranslucency` holds the settings of the per-pixel sorted translucency, each an option of `createWorld` too. By default the translucent layers blend in the order they are drawn, objects far to near. With `oitSortedPixels` (`false`, the default; the project switch, read once when the session opens, because the programs of the layers are made with it) the layers of blending `normal` and `additive` are not blended but collected: each fragment puts its light, its transmittance and its depth in a short list its pixel holds, and once the pass has drawn the layers a full-screen pass sorts every list by depth and composes it front to back over what the pass drew apart from them (the other blendings, the transmissive layers, the water and the particles), so two layers that cross are ordered right at every pixel. `oitSortedPixelsEnable` (`true`) is the switch read each image. `oitPassType` (`3`, from `0` to `3`) is a set of bits, `1` the standard translucency and `2` the separate one; every layer the engine draws is drawn apart from the lit image, so the bit `2` decides and the bit `1` changes nothing. A pixel keeps `oitMaxSampleCount` fragments (`4`, from `1` to `16`, rounded down to a square: `8` keeps `4`). `oitMethod` picks how: `1`, the default, the multi-layer alpha blending, keeps the fragments in depth order and merges the ones past the room into the last, dropping a fragment that lies behind a stored one whose transmittance is under `oitTransmittanceThreshold` (`0.05`, from `0` to `1`) in every channel; `0` the k-buffer, keeps the first fragments to arrive and drops the rest. The buffer is `96` bytes a pixel at the default (more where the pool has grown, see below) and needs a device whose fragment stage binds nine storage buffers (its own limit, `maxStorageBuffersInFragmentStage`, where the browser lists one, and the limit every stage shares); a device that grants fewer, an image with display layers (`displayFilter`), or a buffer the device cannot bind keeps the layers blended in drawing order. Deliberate differences from the reference, which sorts under a raster-ordered view WebGPU does not have: the fragments are only appended (a slot of the pixel taken by an atomic add, a node of a shared pool by another, linked at the head of the pixel's list by an atomic exchange: no lock, no wait, no fragment given up for contention), and the sort, the transmittance threshold and the merge of the fragments past the room into the last are made by the full-screen pass, ties broken by the packed words, so that the image is the same whatever order the fragments arrive in and equals the reference's for fragments met nearest first and at most one past the room (the layers are drawn nearest first while the sorting is on, as the reference does). The multi-layer method lists every fragment a pixel receives, as the reference's lock never drops one: the pool of nodes holds `oitMaxSampleCount` nodes a pixel at least and is grown (doubled at least, the old buffer retired, never shrunk) to the number of nodes the fragments of the last images asked, read back a few images late, up to what the device binds. The image that outgrows the pool loses no light either: a fragment the pool has no node for adds its light and the logarithm of its transmittance to sums the pixel holds in whole numbers (an exact sum, whatever the order the fragments arrive in), and the full-screen pass merges those sums into the last layer as the reference merges a fragment past the room (the light added through the last layer's transmittance, the transmittances multiplied) — an approximation of the reference for those fragments, whose own order and mutual occlusion are not known; the pool is right-sized from the next image on. The same merge takes the fragments the sorted array pushes out: the pass walks each list once, inserts each fragment into the array of the `oitMaxSampleCount` nearest (a cost of the fragments times the samples), and sums the pushed-out light unweighted by one another, so that with more than one fragment past the room the merged light is the sum of their lights through the last layer rather than the reference's front-to-back chain. The k-buffer keeps the first fragments to arrive and drops the rest, as the reference does. The fragments are tested against the depth the blended layers are tested against (water included). The composed alpha is the target's alpha multiplied by the mean transmittance of the sorted layers (the reference writes the mean transmittance over the alpha, losing what the layers drawn apart from the sorted ones left in it). `oitDebug` (`0`, from `0` to `3`; `2` for the separate translucency) writes over the image the method, the samples kept and, at the pixel `oitDebugCursorX`, `oitDebugCursorY` (`-1`, none; the pixel must lie inside the image, off its first row and column and its last), that pixel's count and each fragment's depth, light and transmittance.

```js
const world = createWorld('viewer', { oitSortedPixels: true }) // crossing glass panes and additive sprites sorted per pixel
world.orderIndependentTranslucency = { oitMaxSampleCount: 9 } // nine fragments a pixel, for deeper stacks of layers
world.orderIndependentTranslucency = { oitMethod: 0, oitMaxSampleCount: 16 } // the k-buffer, sixteen fragments
world.orderIndependentTranslucency = { oitSortedPixelsEnable: false } // blended in drawing order again, without rebuilding the programs
world.orderIndependentTranslucency = { oitDebug: 2, oitDebugCursorX: 640, oitDebugCursorY: 360 } // the samples of the pixel at (640, 360)
world.orderIndependentTranslucency = { oitMaxSampleCount: null } // back to the default, 4
```
